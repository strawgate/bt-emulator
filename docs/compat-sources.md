# Braintrust-owned compatibility corpus inventory (bt-emulator)

Surveyed 2026-11-16 across the public `braintrustdata` GitHub org.

**Source policy.** bt-emulator only uses public, permissively licensed (MIT/Apache/BSD) open-source material, with its license kept alongside it. Nothing is ever recorded or run against Braintrust's hosted API. Every "live mode" below means pointing a suite at a local bt-emulator, never at braintrust.dev. Repos without a license (marked **none**) are listed for completeness only and are not used, not even to run.

Licenses come from each repo's top-level LICENSE file.

## Per-source notes

### 1. braintrust-openapi (the canonical spec)
- Raw URL: `https://raw.githubusercontent.com/braintrustdata/braintrust-openapi/main/openapi/spec.json` (returns 200); `.../openapi/spec.yaml` also exists. Pin it as `.../374478b4a6214e5cf1f32551703bdbc4cea5a7b3/openapi/spec.json`.
- `openapi: 3.1.1`, `info.version: 1.0.0` (the version field never moves, so track the commit SHA instead). Latest commit: "Sync OpenAPI spec (#233)", 2026-11-11. The repo is an auto-sync target.
- 77 paths / 162 operations (GET 56, POST 43, DELETE 26, PATCH 21, PUT 16), 256 component schemas. All 162 ops have an `operationId`, and every 2xx response has a content schema. Only 4 ops have examples. Declared responses: 200/400/401/403/429/500. Security: `bearerAuth` or none.
- The same spec is copied byte-for-byte at the path level into `go/openapi/spec.json` and `braintrust-migrate/openapi_spec.json` (same 77/162; the JSON is not identical).
- **Not in the spec** (these come from cassettes and mocks instead): `/api/apikey/login`, `/api/project/register`, `/api/experiment/register`, `/api/dataset/register`, `/api/base_experiment/get_id`, `/api/self/me`, `/api/project_automation/*`, `/logs3`, `/logs3/overflow`, `/btql`, `/version`, `/attachment*`, `/otel/v1/*`, `/insert-functions`, `/function/invoke|use|code|sandbox-list`, `/experiment-comparison2`, `/dataset-summary`.
- Schemathesis suitability: good for `/v1/*` CRUD. Use `--checks all` with stateful links off at first, because the spec has no OpenAPI `links` (stateful sequences have to be hand-written). For PUT (upsert) and the list endpoints, expect noise from `nullable`/union-heavy schemas. The Rust SDK's overlay `braintrust-sdk-rust/crates/braintrust-api-client/openapi-client.overlay.yaml` (38 lines) documents known real-vs-spec gaps: Dataset `created_at` vs `created`, `/v1/proxy/{path+}` catch-all, nullable `SavedFunctionId` intersections, and forward-compatible topic settings. Apply the same overlay before fuzzing.

### 2. braintest-suite (highest-value live suite; no license)
- `src/braintest_suite/functional_test/run.py` (1523 LOC) holds `core_steps`, which runs create-then-read for the following, then cleans up: project, attachment (signed upload + status), project_logs insert/fetch, logs3, logs3 overflow (signed-URL upload of the payload), OTel ingest (JSON + protobuf, checks `partialSuccess`), role, group, dataset, experiment, prompt, ACL, project_automation (`btql_filter`), project_score, project_tag, function, view, api_key, env_var, environment.
- Configuration (pydantic-settings, env takes priority over YAML): `BRAINTRUST_API_KEY` (env), `BRAINTRUST__API_URL` (strips a trailing `/v1`), `BRAINTRUST__PROJECT_NAME`, `FUNCTIONALTEST__NAME_PREFIX`. File: `braintest.yaml`.
- Run: `uv sync && BRAINTRUST_API_KEY=x BRAINTRUST__API_URL=http://localhost:PORT uv run braintest run functional`, and likewise `run evaltest` (builds a 100-row dataset and runs an eval, no LLM). `loadtest` is Locust and uses the SDK logger plus `/btql`. `topics` makes LLM calls, so use `TOPICS__DRY_RUN=true` or skip it.
- It exits non-zero if any record FAILs, so it works as a CI gate as is. There is no LICENSE, so pin it as an external checkout and never vendor it.

### 3. terraform-provider-braintrust
- Acceptance: `scripts/test-acceptance.sh` → `TF_ACC=1 go test -v -p 4 -parallel 4 -timeout 1200s ./internal/provider/`. There is also `make test-acceptance-local` (`BRAINTRUST_API_URL=http://localhost:8000`).
- Env: `BRAINTRUST_API_KEY`, `BRAINTRUST_API_URL`, and optionally `BRAINTRUST_TEST_ORG_ID`, `BRAINTRUST_TEST_USER_ID`, `BRAINTRUST_TEST_USER_EMAIL`, `BRAINTRUST_SERVICE_ACCOUNT_ID`, `BRAINTRUST_ORG_ID`. When these are unset, `scripts/braintrust-key.sh` derives them with `GET /v1/organization?limit=100`, `GET /v1/user?limit=1` and `GET /api/self/me`, so the emulator must implement those three. It also needs `terraform` and `jq`.
- The 40 acceptance tests cover full plan/apply/refresh/destroy lifecycles, so they check PATCH semantics, drift detection and import. That makes them very strong CRUD-fidelity tests.
- `tests/offline/*` (6 files) and `tests/compat/*` use `httptest` fixture APIs (`baseFixtures()` in `tests/offline/offline_test.go`). These encode the list-response shape (`objects`), the ACL `_object_org_id` field and so on. They are reusable as expected shapes.

### 4–7. SDK cassette corpora (replay plus live mode)
To harvest any of them, parse each interaction, rewrite the host to the emulator, and replay each cassette in order against a fresh emulator with seeded fixtures. Compare status and JSON shape, not IDs or timestamps. Login responses carry `org_info[].api_url`, which the emulator must rewrite to itself.
- **Go** (`go`): BT cassettes are in `api/`, `eval/`, `evalrunner/`, `openapi/`, `prompt/`, `btx/`, `internal/https` `testdata/cassettes/*.yaml`. `go/internal/vcr/vcr.go` reads `VCR_MODE` (`replay` default / `record` / `off`) and `BRAINTRUST_API_URL`; see also `go/internal/tests/session.go:98`. Live run: `VCR_MODE=off BRAINTRUST_API_KEY=x BRAINTRUST_API_URL=http://localhost:PORT go test ./api/... ./eval/... ./prompt/... ./openapi/...`. The `trace/contrib/*` cassettes are provider traffic and would need real LLM keys in `off` mode, so exclude those packages.
- **Ruby** (`braintrust-sdk-ruby/test/fixtures/vcr_cassettes/{api,auth,btql,dataset,datasets,eval,eval_functions,experiments,functions,projects,prompt}`): 449 BT interactions. Hosts: www.braintrust.dev 205, staging-api.braintrust.dev 156, api.braintrust.dev 88. `test/test_helper.rb:59-70`: `VCR_OFF=true` allows real HTTP, and `VCR_MODE=<record mode>` sets the record mode. Live: `VCR_OFF=true BRAINTRUST_API_KEY=x BRAINTRUST_API_URL=... BRAINTRUST_APP_URL=... bundle exec rake test`. I have not verified that Ruby reads both URL env vars; `lib/braintrust/config.rb` has `api_url`/`app_url` attributes.
- **Java** (`braintrust-sdk-java/test-harness/src/testFixtures/resources/cassettes/braintrust/{mappings,__files}`): WireMock stubs with `scenarioName`/`requiredScenarioState`, so the stubs carry their call order. They record full response headers, including `x-bt-*` expose headers. `/otel/` and `/attachment` are never recorded (`VCR.java:67`, `PASSTHROUGH_PATH_PREFIXES`) and get catch-all stubs in replay. `VCR.java:91` reads `VCR_MODE` (replay/record/off). The Braintrust target is `envConfig.apiUrl()`, i.e. `BRAINTRUST_API_URL` (`TestHarness.java:96-110`). `VCR_MODE=off` proxies **every** target, so provider tests then need real keys. Restrict the run with `./gradlew :braintrust-sdk:test --tests '*Api*'` or similar, or patch VCR to stay in replay for the provider targets only.
- **Python** (`py/py/src/braintrust/{,api,devserver}/cassettes`, plus a few integrations dirs: harbor, pipecat, anthropic, cursor_sdk): 219 BT interactions. Format: vcrpy v1 YAML, `pytest-vcr`; record mode is `none` in CI and `once` locally (`conftest.py:183`). There is a nox flag `-- --disable-vcr` (`noxfile.py:8,1171`). **Blocker:** the autouse fixture `override_app_url_for_tests` (`conftest.py:81-106`) forces `BRAINTRUST_APP_URL=https://www.braintrust.dev`. A live run against the emulator therefore needs either a local conftest patch or a MITM proxy that maps www/api.braintrust.dev to the emulator. My count (1068 parseable cassettes) is lower than the ~1200 known files; the rest are non-cassette YAML or failed to parse.

### 8. JS SDK e2e harness (mock server + prod forwarding)
- `e2e/helpers/mock-braintrust-server.ts` (838 LOC) is Braintrust's own minimal emulator. Its route list is in the table; it returns `/version` → `{}` and `/api/base_experiment/get_id` → 400 `{"error":"No base experiment"}`. The canned responses document the minimum contract the SDK accepts.
- `e2e/helpers/scenario-harness.ts:266-273` starts each scenario subprocess with `BRAINTRUST_API_URL/APP_URL/APP_PUBLIC_URL/PROXY_URL` all set to the mock.
- **Prod forwarding** (`e2e/helpers/prod-forwarding.ts`): if `BRAINTRUST_API_KEY` is set, the mock logs in with `initLogger({appUrl: BRAINTRUST_APP_URL})`. It then forwards `/api/project/register`, `/api/experiment/register`, `/attachment*`, `/logs3` and `/otel/v1/traces` to the resolved `apiUrl`/`appUrl`. Running `BRAINTRUST_API_KEY=x BRAINTRUST_APP_URL=http://localhost:PORT pnpm test:e2e` (from the repo root; `e2e/package.json` → `scripts/run-e2e-tests.mjs`) therefore mirrors all 66 scenarios' real SDK writes into the emulator. LLM calls still replay from the seinfeld cassettes, and the snapshot assertions still pass against the mock. Afterwards, check that the emulator's stored rows match `__snapshots__/span-tree.json` (BTQL/fetch readback). This is the cheapest way to get high-volume, realistic ingest traffic.
- Snapshots: `e2e/scenarios/*/__snapshots__/{span-tree,request-flow,*}.json|txt` (698 files). These are normalized SDK→server payloads (`api_version: 2` logs3 rows, OTel). Three `request-flow.json` files hold captured request sequences (80 captured requests: 56 otel, 9 logs3, 7 login, 7 register, 1 version).
- Unit tests in `js/src/*.test.ts` (e.g. `logger.test.ts`, `background-logger.test.ts`, `logger-caching.test.ts`, `logs/logs.test.ts`) mock fetch for `/logs3`, `/version` and `/api/apikey/login`. That is mid value, as reference only.

### 9. braintrust-spec `test/llm_span` (no license)
- 30 YAML specs with `expected_brainstore_spans`. `test/IMPLEMENTATION-GUIDE.md` defines a **live mode**: log through the SDK, then `POST $BRAINTRUST_API_URL/btql` with a JSON-AST query (`use_columnstore/use_brainstore/brainstore_realtime: true`, filter on `root_span_id`, sort by `created`). It retries for up to 600 s, waiting while `output==null && metrics==null`, and drops spans with `span_attributes.purpose=="scorer"`. Env: `BRAINTRUST_API_KEY`, `BRAINTRUST_API_URL`, `BRAINTRUST_PROJECT`/`BRAINTRUST_DEFAULT_PROJECT_NAME`.
- Runners: `py/py/src/braintrust/btx/` (spec ref `v0.0.13` in `spec-ref.txt`; provider cassettes in `integrations/*/cassettes/latest/btx/`) and `braintrust-sdk-java/btx/src/test/java/dev/braintrust/sdkspecimpl/`. In both, live mode means VCR off for all hosts, so it also needs real LLM keys. A small patch fixes that: keep provider replay and let the emulator host through (vcrpy `ignore_hosts=['localhost']`). The result is a write→merge→BTQL-readback roundtrip test across 2 SDKs, and it checks BTQL AST parsing.
- Also useful as reference specs: `semconv/span_attributes.yaml`, `semconv/envar.yaml`, `skills/instrumentation-spec/references/features/*.md` (attachments.md defines the login/org-id and attachment upload contract).

### 10. Stainless legacy SDKs (archived or "no longer maintained")
- Every generated test reads `TEST_API_BASE_URL` (default `http://localhost:4010`, Prism). Examples: `braintrust-go/project_test.go`, `braintrust-api-py/tests/api_resources/*` (`base_url = os.environ.get("TEST_API_BASE_URL", ...)`), `braintrust-java/.../TestServerExtension.kt:58`. `scripts/test` skips starting Prism when `TEST_API_BASE_URL` is set. The Prism spec URLs in `.stats.yml` (storage.googleapis.com stainless bucket) now return **404**, so these suites can't run as shipped at all. That makes the emulator a natural replacement.
- Caveat: the tests send placeholder values (IDs like `182bd5e5-6e1a-4fe4-a799-aa6d9a6ab26e`, names `"x"`) and assert only "no error". Py/Java/Kotlin also strictly validate the response type (`assert_matches_type`, `.validate()`). To be useful, the emulator needs a "prism-compat" mode that auto-materializes unknown IDs. Without it you get mostly 404s. Value: response-schema conformance at ~1000 calls. Low semantic depth.
- Commands: py `TEST_API_BASE_URL=... ./scripts/test` (pytest); go `TEST_API_BASE_URL=... go test ./...`; js `TEST_API_BASE_URL=... ./scripts/test` (jest); ruby `./scripts/test`; java/kotlin `TEST_API_BASE_URL=... ./gradlew test`.

### 11–15. Mock-based suites (behavior reference, not directly runnable against the emulator)
- **bt CLI** `bt/tests/{cli,functions,datasets,eval_dev_server,eval_fixtures,sync,custom_ca}.rs`: actix/TcpListener mock APIs. `BT_FUNCTIONS_FIXTURE_LIVE=1` enables the live fixtures in `functions.rs:448`. Better approach: script `bt` commands (`bt projects`, `bt datasets`, `bt functions push/pull`, `bt sync`, `bt eval`) with `BRAINTRUST_API_URL/APP_URL/API_KEY/ORG_NAME` pointed at the emulator, using the `tests/functions-fixtures` and `tests/datasets-fixtures` inputs.
- **Rust SDK** `braintrust-sdk-rust/tests/*.rs` and `crates/braintrust-api-client/tests/*.rs`: wiremock `Mock::given(path(...))` stubs. These are the best documentation of logs3/overflow batching (`tests/logs3_uploader.rs`), and of the register endpoints plus `/dataset-summary` and `/experiment-comparison2`. `tests/eval_test.rs` is `#[ignore]` live (requires creds).
- **.NET** `tests/Braintrust.Sdk.Tests/Eval/StubBraintrustApi.cs`, `QueuedHttpHandler.cs`, `Api/Internal/BtqlClientTest.cs`: these cover the BTQL request shape and `/otel/v1/logs`.
- **braintrust-migrate** `tests/integration/test_live_smoke_real_api.py`, `test_live_e2e_matrix.py`: skipped unless enabled; env `BRAINTRUST_API_KEY` plus `BT_SOURCE_URL`/`BT_DEST_URL` (see docstrings at lines ~88/130). The emulator can host both source and dest orgs. These are heavy users of BTQL pagination, `/v1/acl/list_org`, `/v1/column`, `/v1/organization/members` and `/v1/span_iframe`.
- **coding-agent-plugins** `.github/scripts/mock-braintrust.py` (86 LOC): the smallest mock of the SDK contract (`/version`, `/api/apikey/login`, `/api/project/register`, `/logs3`, `/logs3/overflow`).

1. Vendor the OpenAPI spec (Apache) at its pinned SHA, then run schemathesis over `/v1/*` with the Rust overlay applied.
2. Run the terraform acceptance suite (40 lifecycles) against a local emulator.
3. Extend the cassette-replay harness (`tests/compat.rs`) over the Go (292), Ruby (449), Java (251) and Python (219) BT interactions, about 1,211 recorded request/response pairs in total. Vendoring is fine for Apache/MIT; keep the MIT notice for Java cassettes.
4. Run the SDK suites with Braintrust traffic pointed at a local emulator: Go `VCR_MODE=off` (non-contrib pkgs), Ruby `VCR_OFF=true`, Java `VCR_MODE=off` (Braintrust-only tests, no LLM calls), and JS e2e with forwarding to the emulator.
5. Use the Apache-licensed Stainless suites with `TEST_API_BASE_URL` once a permissive ID mode exists.
